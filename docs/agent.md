# 智能体「小雷」

管理员在任何页面（前台、后台）都能叫出小雷：右下角的小雷按钮，或 `⌘J` / `Ctrl+J`。宽屏停靠在右侧、页面让出位置；窄屏是抽屉；手机是全屏。对话和开合状态跨页面保留，`Esc` 收起。后台「小雷助手」（`/admin/agent`）是同一组对话的整页视图。访客看不到小雷，前台页面的 HTML 对所有人一样（浏览器里请求 `/api/admin/me` 后才显示）。

它做两类事：在资料库里检索、带出处回答；替管理员查后台、办事。

## 配置

小雷用站点的默认模型，也就是 `.env` 里的 `LLM_BASE_URL`、`LLM_API_KEY`、`LLM_MODEL`（`LLM_EXTRA_JSON` 同样生效），和研究功能是同一个，不需要另外配置。默认模型要支持 JSON 输出（`LLM_JSON_MODE` 不设为 `false`）。

还要开着 `MODEL_CALLS_ENABLED`。每一步模型调用都走回执和 `llm` 预算熔断，费用在「运行」和回执里看。

## 它能做什么

### 资料库问答

`search_knowledge` 检索（`packages/backend/src/knowledge/search.ts`，不加付费服务、不需要向量库）：

- 文章：全部信源已抓到的正文（公众号、博客、HN、主动搜索等），不受公开全文开关 `site_fulltext` 限制（只有管理员能问，前台展示规则不变）；没正文的用摘要；撤回的不用。
- 微信群：已生成的群摘要要点；命中原消息时取前后各 10 条作为一段对话。发言者换成“发言者N”，手机号、邮箱等按群摘要的规则脱敏，昵称不发给模型。
- 排序按命中的段落（约 500 字一段），不是按文章日期，长文后半段的证据也能取到。可按信源/群名、单篇文章、类型、起始日期过滤。

检索完后模型调用 `answer`，worker 基于本轮全部片段流式写回答，每句用 `[n]` 标出处；页面上点角标或下面的引用列表看原文片段，可跳站内页面或原文。在文章页打开小雷会带上“正在看”的文章，“这篇”就指它（可点 × 去掉）。

旧的「研究记录」（`/admin/research`）保留可看，新的问答都在小雷里。

### 后台查询与操作

查询类，直接执行：

| 工具 | 作用 |
|---|---|
| `list_sources` / `source_detail` | 信源列表、单个信源的配置、统计、最近采集和文章 |
| `archive_status` | 公众号历史归档进度 |
| `search_content` / `content_detail` | 搜内容、看一条内容的处理链 |
| `runs_overview` | 队列、失败任务、待处理回执 |
| `spend_summary` | 最近几天各服务的请求次数和费用 |
| `search_knowledge` | 检索资料库（文章正文、群摘要、群聊原消息） |

写操作，先出确认卡，点「冲！」才执行，点「算了」或直接发新消息就作废：

| 工具 | 作用 |
|---|---|
| `create_source` / `update_source` | 新建信源；改名称、启停、间隔、级别、参与方式、标签，或合并修改配置（例如把 `listProvider` 改成 `dajiala`） |
| `fetch_now` | 立即采集 |
| `archive` | 公众号历史列表、补全文、暂停 |
| `set_visibility` | 公开 / 只展示摘要 / 撤下 |
| `rerun` | 重新抓正文、重新分析、重新归组 |
| `merge_stories` | 合并事件 |

确认卡写明改前改后和大概费用。执行时调用后台同一套函数，审计记录里的执行人是当前管理员。确认时如果数据已被别处改过（版本变了），会报冲突，不会覆盖。

不开放：预算、模型切换、密钥与设置、反馈处理、回执释放，以及信源的全文授权（`site_fulltext`、`syndicate_fulltext`）和主体归属，这些仍在原页面处理。

## 安全边界

- 模型只在 worker 里调用，页面只轮询对话状态。
- 发给模型的信源配置会隐藏名字里带 key、token、secret、cookie、password 的字段。
- 群聊片段发给模型前匿名化、脱敏；检索命中的群消息和文章片段会发给站点默认模型（`LLM_*`），按次付费。
- 工具结果和文章内容只当资料，系统提示要求模型不执行其中的指令；写操作无论如何都要人工确认。
- 对话存在 `settings` 表（`agent:<id>`），只有本人能看到自己的对话。
