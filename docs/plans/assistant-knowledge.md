状态：实施中（2026-10-16 开工）。

- 全文放开：所有已抓到的正文都可用于问答（只限管理员；前台展示规则不变）。

## 现状（2026-10-16 审查）

数据（本机库）：

| 来源 | 条数 | 有正文 | 可研究（受 `site_fulltext` 限制） |
|---|---|---|---|

| Tavily `external` | 245 | 107 | 只能用摘要 |
| RSS 博客 / Reddit | 165 | 150 | 只能用摘要 |
| 微信群消息 | 374,174（6 群） | — | 完全不可研究 |
| 微信群摘要 `wechat_digests` | 1117 | — | 完全不可研究 |

正文合计约 490 万字。`embeddings` 表为空（没配向量服务），库里只有 `pg_trgm`，没有 pgvector。

问题：

1. **两个助手各管一半。** 小雷（`/admin/agent`）能查后台、办事，但不读文章；研究（`/admin/research`）能带引用回答，但必须先选一篇文章当种子，不能直接问“刘小排怎么看 X”。两边对话记录也分开。
2. **小雷只在后台。** 前台和后台是两套外壳，从文章页想问一句要跳到后台独立页，丢掉阅读上下文。
3. **前台入口对访客是死链。** `item.tsx`、`mp.tsx`、`mp-article.tsx` 的“引用本文，开始研究”“引用并提问”对所有人展示，未登录点进去是后台登录页；`/mp` 的“管理订阅与历史归档”同理。
4. **检索质量差（2026-10-06 审查的 P2，仍未修）。** `publication/research.ts`：按发表时间而非相关度取 5 篇；每篇只截前 9000 字，命中段落在后半段时模型拿不到；只匹配整词 ILIKE。
5. **大部分资料没法内化。** 非公众号的正文因 `site_fulltext` 关闭不能进研究；群聊（最大的语料）完全没接入。研究走的是公开读取层，所以被公开全文权限卡住。
6. 小雷回答不流式（JSON 一步一步轮询），不适合长篇带引用的回答。

## 目标

- 小雷是全站唯一的助手：任何页面（前台、后台）一键唤醒，记住对话，自动带上当前页面上下文。
- 小雷能在**全部信源**（文章正文、群聊、群摘要）里检索作答，每个事实带可点开的引用（原文片段 + 链接）。
- 后台办事能力（确认卡）保持不变。

## 设计

### 1. 全站对话面板 `AssistantDock`

- 挂在 `root.tsx`，前台外壳和后台外壳都渲染；只有管理员看得到（客户端请求 `/api/admin/me` 判断，不进服务端渲染，前台页面的公共缓存不受影响；同 `/wechat` 的私人页做法）。
- 形式：宽屏（≥1280px）是右侧停靠面板，推开主栏，不遮内容；窄屏是右侧抽屉浮层；手机是全屏底部弹层。收起时右下角一个小雷头像按钮，`⌘J` / `Ctrl+J` 切换。开合状态和当前对话 id 记在 localStorage。
- 页面上下文：在文章 / 公众号文章 / 事件 / 群摘要页打开时，输入框上方出现“正在看：《标题》”标签，随消息发给后端，可点 × 去掉。文章页原“引用本文，开始研究”改成“问小雷”按钮（仅管理员可见），点了打开面板并带上这篇。
- `/admin/agent` 保留为完整历史页，复用同一组件。研究记录页保留只读，不再新增；新对话都在小雷里。

### 2. 统一后端：小雷加知识工具，最终回答流式输出

- 新只读工具 `search_knowledge { q, sources?, kinds?, since?, until?, context? }`：返回最多 12 个片段，每个片段带 `ref`（文章 id / 群+日期）、标题、信源、时间、链接、片段原文。
- 模型循环不变（JSON `{say, action}`，最多 6 步）；新增 `answer` 动作：检索够了以后，worker 用 `chatStream` 基于本轮收集的片段写最终回答，边写边存，页面边读边显示（沿用研究的 400ms 刷写）。回答里 `[n]` 对应片段，存进消息；没检索就回答的事实性问题，系统提示要求先检索。
- 新消息类型 `{ role: "agent", text, citations: Citation[] }`，旧对话兼容。

### 3. 检索（第一期不加迁移、不加付费服务）

放在 `packages/backend/src/knowledge/`（私人读取，不放公开读取层 `publication/`）：

- 文章：全部信源的 `body_text`（管理员私用，不受 `site_fulltext` 限制；主人已确认），无正文退回摘要；撤回的不用。
- 群聊：`wechat_digests.points` 作为一级片段；命中原消息时取前后 ±10 条作为一段。
- 打分：`Intl.Segmenter` 分词 + 标题/正文命中数 + 短语完整命中加权 + 信源/作者名过滤（“刘小排”识别成信源过滤），在 SQL 里取候选文章，JS 里按段落切块（约 600 字）再排序，取命中段落而不是开头。
- 规模估算：正文 490 万字顺序扫描毫秒级；群消息 37 万条 ILIKE 预计百毫秒级，后台单人用可接受，实测慢再加 trgm 索引（那是迁移，到时再问）。

### 4. 第二期（另行确认）

- 向量召回：配 DashScope `text-embedding-v4` 后，按段落切块存向量做混合检索。全量一次性约 300 万 token，估算几块钱；需要新表或放宽 `embeddings.kind` 约束（迁移）。
- 沉淀：把小雷的回答存为“笔记”（带引用），收藏页可看；按公众号生成“观点地图”（主题 → 观点 → 引用），新文章到达时增量更新。
